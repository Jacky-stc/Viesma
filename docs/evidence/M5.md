M5.2 adapter 的預設 key 由 Node.js CSPRNG 產生，隨記憶體 repository 存活。HMAC 輸入以帶版本的 JSON tuple 編碼 deathId、ownerCharacterId、tableEntryId 與 counter。Loot ID、entry ID、原始 balanceVersion、物品 ID／數量或貨幣金額，連同來源地圖、instance 和死亡座標一併凍結。成功收據保留原始 UTC 到期時間，同一 repository 可在資料或 key 更新後讀回。記憶體收據的保存範圍為單一程序。

M5.3 負責背包、裝備與角色 mutation。M5.4 負責安全地板落點、delivery instance、owner-only payload、拾取與消耗品指令。M5.5 負責將抽取接上現行 reward worker、以同一筆記憶體交易原子提交 EXP 與 ground grants，並以該交易的成功時間起算 expiry。

#### M5.2 本機驗證

- **環境**。2026-11-25，Windows 11 26200，Node.js 24.22.3、pnpm 11.19.0、Vitest 5.1.1、Playwright 1.65.1、Chromium 159.0.8154.6。以本機快取工具鏈覆蓋本次指令的 PATH，解決系統預設 Node.js 24.18.0。Vitest 與 smoke 透過可用 loopback 的執行環境，smoke server 使用 `VIESMA_SERVER_PORT=25767`。
- **實作前 HEAD**。`d124530421967fb61dc6c1998f4a569be1219c6a` 的 `pnpm run test` 通過 464／464，`pnpm run build` 通過。`pnpm run test:smoke` 收集 22 項，序列多人 7／8、其餘 14／14。延遲進房重連案例報告 Playwright 的 `Fetch response has been disposed`。最初在網路受限沙箱執行 Vitest 時有四項 loopback 測試連線失敗，授權後在同一 HEAD 驗證通過。
- **工作樹檢查**。`pnpm run typecheck`、`pnpm run lint`、`pnpm run check:boundaries`、`pnpm run format:check`、`pnpm run build`、`pnpm run validate:maps`（七圖）與 `pnpm run validate:assets`（七個 sprite 定義）皆通過。`pnpm run test` 通過 507／507（31 個檔案，較基線新增 43 項）。正式 client 建置產物未含伺服器 loot RNG 的 domain 標記。
- **完整 smoke**。`pnpm run test:smoke` 通過 22／22，序列多人階段 8／8（1 worker，約 1.7 分鐘）、其餘 14／14（5 workers，43.4 秒）。涵蓋基線曾失敗的延遲進房重連案例，以及 150 ms RTT 雙瀏覽器換圖與重連。沿用既有 assertions、timeouts 和 smoke runner。
- **M4.5 耐久**。本次略過。新結算 adapter 在 M5.2 以獨立契約及測試夾具驗證，正式 reward worker、room receipt 的使用與釋放、角色持有權的執行路徑沿用 M5.1。
- **待驗證**。M5.2 實作提交的遠端 CI 尚待執行。本次使用 Chromium 橫向觸控模擬，第一輪真機 iPhone Safari／Android Chrome 驗收另依路線圖執行。
